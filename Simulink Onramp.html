Transcript

Engineers often need to create and simulate models of real-world components and systems in order to predict their behavior. A common way to do this is to start with a block diagram, which is a visual representation of system components, their underlying math, and the connections between these components.

The next step is to move from the block diagram to simulation. That's where Simulink comes in. By connecting and grouping blocks, you can model components and algorithms. You can then simulate your model just by pressing run and inspect its behavior with various readouts.

The graphical layout makes it easy to model systems like this motor controller, or even an entire aircraft. If this looks complicated, don't worry. In this course, we'll walk you through modeling dynamic systems from the very beginning.

We'll learn about adding and customizing blocks, integrating custom MATLAB functions with Simulink, creating filters, and representing dynamic systems. Finally, you'll apply your knowledge with some projects. You'll implement the logic for an automotive performance package, model a thermostat, and capture the dynamics of a diving peregrine falcon.

Since Simulink is built on top of MATLAB, it will help to have a basic familiarity with the language. If you've never used MATLAB before, it's easy to get started. We recommend you first take MATLAB Onramp to get you up to speed quickly.

It's also helpful to have a working knowledge of ordinary differential equations. Don't worry, we won't ask you to solve any, but we will model them. Throughout this course, you'll be completing tasks in the Simulink Editor.

It's the same Simulink Editor you'll encounter outside of this training, but with a few added features on top. In particular, each task will have one or more assessment blocks. These blocks are unique to the training environment and provide you with feedback when you submit a task.

Depending on the type of block, they evaluate either the connected signal or the overall properties of the model. And with that, you're ready to go. Let's get started!

Reading: Introduction

Simulink Basics
As you've just seen, Simulink uses graphical elements to represent the inputs, outputs, and calculations within a simulation. Signals make connections between blocks at ports.
A signal is a piece of information, such as a numeric value, that can change over the course of a simulation. Blocks accept signals at input ports, perform an operation, and return signals at output ports. Signal lines are visual elements that connect block ports and show where a signal flows: from output ports to input ports, and in the direction of the arrow.
To connect blocks, first click on a port. All possible connections will be highlighted. Click on one of the highlighted ports to create the connection.
When two ports are aligned, Simulink displays a suggested connection. Click on the suggestion to create a signal line.
You can also create a signal connection by clicking and dragging from one port to another.
When you have finished creating your model, click Run to simulate it. Run is located in the Simulation tab of the Simulink toolstrip. As a reminder, in this training environment, clicking Submit also runs the model.
Click Next to start creating your first Simulink model.

The simulated signal is a discrete sine wave. The "noise" is added by superimposing a higher frequency sine wave. The noisy signal is passed through a filter that averages the signal's current value with its previous value. Transcript

As you've just experienced, you can use Simulink Scopes to monitor signals in your simulation. Just like an oscilloscope, you can examine signals while the model runs as well as record data for further analysis. But Scopes do more than just plot outputs, so let's explore what else you can do with them.

The simulation controls are reproduced in the Scope display so that you can run, pause, and step through your simulation while viewing the signal values. You can inspect a signal in more detail using the zoom tools, which allow you to zoom in on a selection or a particular axis.

The pan and auto-scale tools also help you find what you're looking for. The Scope toolstrip contains additional options. You've already toggled a legend using the Settings menu. The full Settings dialog has more options for customization, including the ability to automatically open the Scope with the model or log the Scope data to the MATLAB workspace.

You can post-process or visualize this logged data using Matlab or the Simulation Data Inspector. You can also adjust the Scope's display grid. For example, you can put each signal on a separate subplot or combine them. If you have multiple scopes, you can dock them all to a single window to have all of your results in one place.

The toolstrip also has a Measurements tab, which has tools to make common measurements on the signals. Enabling data cursors, for example, allows you to trace signals and estimate the period or slope between two points of a signal.

If you have toolboxes other than Simulink installed, you may find additional items here, like the Peak Finder. Finally, like a MATLAB plot, you can customize the line styles, add markers, and adjust the axes limits for Scopes.

Use the Scope's Help menu to access the Scope documentation page to learn more.

8.1 Dynamic Systems

Learning outcome: Dynamic systems and their relationship to Simulink

This lesson includes 1 video.

If you prefer text, review the video summaries and transcripts. They are provided so you can work through the lesson without relying on the original media player.

Video: Dynamic systems video

Open the video in a new tab

This alternate format includes an HTML5 video player and transcript so you can review the lesson without relying on the original platform.

Transcript

Engineering is full of dynamic systems. Dynamic systems have states whose values evolve over time. A state is just a type of quantity like position or population, that depends on previous states as well as other properties of the system.

For example, states depend on the initial conditions, physical characteristics of the system, and any external inputs. System outputs, in turn, are dependent on the states. Dynamic systems can be discrete or continuous. With discrete systems, we monitor the states at specific time points.

The dynamics are described by difference equations. The current state typically depends on the time history of one or more past states. In some systems, we model time as continuous, in other words, for that case that the time between samples approaches 0.

Since we assume infinitesimally small time steps, continuous dynamic systems are described by differential equations. Computationally, we keep track of the derivative of our state instead of the state itself and integrate at each time step.

In Simulink, signals carry the values of states like position or velocity, inputs like gravity, and outputs over time. As always, blocks allow us to express the relationships between these signals. In the next lessons, we'll learn how to express the relationships to model dynamic systems.

Reading: Introduction

Project - Thermostat Model
In Chapter 10, you modeled a first-order cooling equation. That equation could represent the temperature dynamics of a house. To keep the house comfortable, you might want to control the temperature, using a strategy based on the current and desired temperatures. This is called a control system, and is exactly what a thermostat is! Since most controllers are digital, they are often modeled as discrete systems.

A controller measures the error between the set and measured temperatures and sends a command signal based on that error.
     
For example, a very simple control strategy could be to turn the furnace on if the house is cold, and off if it is hot.
     
The result, as shown here, is the proper average temperature, but with a lot of fluctuations.
     
Instead, you can specify the controller output as proportional to the error. For example, if the temperature is close to the set point, little heat is required. If the temperature difference is large, though, the heater should be at maximum power.
     
The result is a much more consistent temperature, but the temperature never quite reaches the set point. To address this, you can also consider the accumulated error over time.
     
This is done by integrating the error and increasing the control effort if the accumulated error grows. This type of control is aptly named proportional-integral, or PI, control.
     
In this project, you model the discrete equations representing a PI controller. The model contains a set temperature and a block representing the house, similar to the model you built previously. You must create the controller.

Reading: Introduction

Project - Peregrine Falcon Dive
When diving for prey, the Peregrine falcon can reach speeds of up to 350 km/h. As the falcon dives, the two forces acting on it are gravity and air drag. The equation of motion for this is:
mdotv = (1) / (2) * rho C_d A v^2 - mg
As it approaches the ground, however, it changes the angle of its wings. This increases drag, which rapidly decelerates it to a safe landing speed. You can model this process in the equation of motion as a change in the area A and drag coefficient C_d. In this project, you must use Simulink to model this behavior in two parts. First, you model the equation of motion for a given set of drag parameters. In the second part, you model the wings opening to slow the bird down.
